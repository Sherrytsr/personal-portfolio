从 0 到 1 设计并实现的对话式饮食推荐 Agent，面向日常“吃什么”的决策场景，结合用户心情、就餐场景与健康诉求，完成从语义理解到餐食推荐、Trace 监控和离线评估的完整闭环。

A conversational meal recommendation agent that turns vague dining needs into a structured, retrievable, rankable, and traceable recommendation workflow.

项目简介Project intro

“吃什么”不是简单搜索，而是动态决策。

“What should I eat?” is not just search. It is a dynamic decision problem.

用户在真实就餐场景中的表达通常模糊、动态且不完整：可能只说“想吃清淡的”，也可能在系统推荐后继续说“换一批”“不要太油”。因此系统不仅要能理解用户目标，还要能维护多轮会话状态，在信息不足时主动澄清，在推荐失败或模型异常时稳定兜底。

Users rarely provide complete requirements at once. They may say “something light,” “I'm tired tonight,” or “give me another batch.” The system identifies intent, extracts slots, clarifies missing information, and supports multi-turn adjustment.

The main pipeline is intent recognition and slot filling, multi-turn slot merge, clarification decision, meal retrieval, rule-based ranking, LLM response generation, and trace-based evaluation.

核心设计Core design

围绕 Agent 可用、可控、可观测、可评估展开。

Designed around usability, control, observability, and evaluation.

01

全链路可观测能力设计End-to-end observability

问题：LLM 输出不稳定，线上问题很难只靠日志判断是哪一步出错。

方案：在请求入口、Agent 调用、槽位合并、澄清决策、检索排序、最终响应等节点记录 Trace，采集输入输出、模型名、Token、耗时与异常状态。

价值：支持按会话还原链路和逐节点回放，能定位意图误判、槽位残留、检索过严、排序排除或模型异常。

Trace captures key inputs, outputs, model usage, latency, and errors so each request can be replayed and debugged.

02

评估体系设计与评估闭环Evaluation loop

问题：推荐质量不能只靠主观感觉，需要稳定的量化指标来指导优化。

方案：批量解析 Trace，综合后端规则、LLM Judge 与用户反馈生成百分制评分报告，覆盖意图准确率、槽位准确率、Token 消耗、延迟、安全合规、幻觉控制等 10+ 指标。

价值：低分样本可以回流到 prompt、规则和餐食库优化，形成 Trace 标注、批量评估、指标驱动迭代闭环。

Trace-based evaluation combines rules, LLM judge, and feedback into measurable quality reports.

03

LLM 全链路 Fallback 设计LLM fallback design

问题：LLM 可能超时、额度耗尽、返回空内容或格式错误，直接依赖模型会导致主流程中断。

方案：意图识别失败时走关键词规则，澄清追问失败时用固定模板，推荐应答失败时用模板生成话术，但推荐卡片仍来自数据库检索排序。

价值：用户感知是回复略模板化，而不是系统报错，保证全链路任一 LLM 异常时对话仍有结果。

Rules and templates take over when LLM calls fail, keeping the conversation available.

04

完整产品设计End-to-end product design

问题：单纯聊天推荐只能完成一次体验，无法支撑偏好沉淀、问题排查和持续优化。

方案：用户侧设计公共/个人双数据源推荐、个人餐食库管理和反馈入口；研发侧设计 Trace 查询、样本标注与批量评估。

价值：覆盖对话推荐、菜单维护、Trace 标注、批量评估四套能力，打通使用、反馈、标注、评估、迭代闭环。

The product connects user experience, feedback, trace review, labeling, and evaluation.

05

后端多 Agent 协作架构Backend multi-agent architecture

问题：如果把理解、追问、推荐、评估都塞进一个大模型调用，逻辑不可控，也不利于定位问题。

方案：采用“编排中枢 + 专职 Worker”分层模式，将意图理解、槽位澄清、推荐生成、质量评估拆成独立 Agent 单元，由 Orchestrator 统一管控状态流转。

价值：LLM 负责结构化推理和语言生成，后端负责确定性流程控制，系统更容易扩展、调试和降级。

Specialized agents are coordinated by a backend orchestrator for clearer control and debugging.

06

意图识别与规则兜底Intent recognition safeguards

问题：用户表达模糊，多轮上下文容易导致错误路由或槽位残留，影响推荐结果。

方案：IntentAgent 识别 6 类意图与 7 维槽位，并叠加意图状态矫正、低置信度降级、关键词 Fallback；槽位抽取通过 diet_slot_option 词典强约束。

价值：降低错误路由、低质量推荐和模型幻觉，让推荐条件更稳定地进入检索排序链路。

Intent recognition is protected by state revision, confidence checks, keyword fallback, and constrained slot labels.
