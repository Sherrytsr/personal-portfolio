02｜核心策略设计与效果验证

知识点 RAG 接入与分层降级

问题：原有 AI 讲题在复述答案和自由追问场景中，可能出现知识点匹配不准、讲解针对性不足，以及公式或概念幻觉。

方案：推动知识点 RAG 接入讲题链路，将首错位置、错因、学生作答及标准知识点结构化注入 Prompt，约束模型按照“错误表现—错误原因—关联知识点—正确应用”的顺序生成讲解，并设计低置信度讲解降级策略。

为什么需要降级：RAG 返回的细粒度知识点可能存在误召回或置信度不足，若直接注入讲题 Prompt，反而可能放大知识幻觉并生成误导性讲解。因此设计分层校验机制：优先使用可靠的细粒度知识点，必要时上收父级；父级仍不可靠时放弃知识库资料，仅依据标准解析生成讲解。是否进一步降为通用讲解，则由首错定位与错因分析的可靠性决定。

验证：搭建自动化评测与人工抽样评测相结合的机制，从知识点覆盖、错因匹配、讲解针对性、易懂度及误导性内容风险等维度评估效果。目前已在2所合作学校的小范围作业错题场景中灰度上线，讲解结果综合评测通过率约95%。

高相似题匹配与 AI 解题兜底

问题：原预录解题链路中仅使用题目文本相似度阈值进行匹配，但专项练习中的题目文本高度相似，轻微 OCR 偏差就可能造成错配。单纯提高阈值会增加漏匹配，也无法有效区分多个高相似候选题。

判断：相比继续提高全局阈值，更关键的是判断系统对 Top1 是否具有明确的选择优势；当 Top1 与 Top2 得分接近时，应主动放弃高风险匹配。

方案：独立设计并推动“最低相关性阈值 + Top1/Top2 分差”的双重判断。只有当 Top1 达到最低相关性要求且明显领先 Top2 时，才复用对应参考答案；候选结果接近或整体相关性不足时，转由 AI 独立解题兜底。

召回候选题→Top1 达到最低阈值？→Top1 明显领先 Top2？→复用答案 / AI 解题兜底

验证：使用线上高相似题错配 Bad Case 进行专项回归，优化后历史错配问题未再复现，验证了 Top1/Top2 分差策略对高歧义匹配的改善效果。

03｜OCR 峰值弹性兜底模型选型

业务问题与方案判断

教师集中批改时，并发可能超过自研 OCR 服务容量，导致部分请求排队、超时或返回 Fail，并中断后续批改链路。问题并非自研模型识别能力不足，而是固定算力难以经济地覆盖偶发峰值。因此，在长期按峰值扩容与外部模型按量调用之间，提出“自研 OCR 承接日常流量、外部模型承接峰值溢出请求”的弹性兜底方案。

评测与选型

基于200条真实峰值溢出请求构建专项评测集，对5个候选模型及 Prompt 组合进行横向评估，从题目识别、学生作答识别、两字段全对准确率及调用成本等维度比较完整生产方案，并结合 Bad Case 完成针对性 Prompt 适配。

选型结论

千问3.8 Max的学生作答识别准确率比豆包2.0 Pro高1个百分点；但豆包2.0 Pro的题目识别准确率高4个百分点、两字段全对准确率更高，调用成本约为千问的1/2～1/3。综合识别效果、错误风险与按量调用成本，最终选择豆包2.0 Pro作为峰值流量兜底模型。

复盘与下一步

目前尚未纳入 P95 延迟和线上月度成本。后续应根据实时队列长度与预计等待时间触发分流，并持续比较外部按量调用与固定扩容的成本拐点，动态调整兜底策略。

04｜线上质量评测与首错归因

评测机制：从真实学校试卷中按学科、题型和判题结果分层抽样，定期运行完整批改链路，并冻结切题、OCR、解题与判题等中间输出。对于 Bad Case，从上游向下游逐节点回溯，定位第一个发生错误的节点，再进入提单、优化与复测闭环。

真实试卷分层抽样→端到端批改→冻结中间输出→定位首错节点→专项优化→分层复测

代表案例｜倾斜试卷导致切题错误

一次线上回流评测中，某套试卷的批改正确率明显偏低。逐节点查看后发现，Bad Case 高度集中在切题环节：试卷存在倾斜，而旧方案使用横平竖直的矩形框处理页面，框过大会混入相邻题目，框过小则会截断题干或学生作答。

试卷倾斜→切题混入 / 截断→OCR 漏识别 / 错识别→参考题匹配失败→残缺题干上解题判题→最终错判

归因验证：将同一批倾斜图片人工转正，在其他条件不变的情况下重新运行完整链路；转正后切题完整性、OCR 内容完整性和参考题匹配均恢复，由此确认旋转与切题是首错节点，而非下游判题问题。

推动方案：将线上 Case 按倾斜角度、学科、版式和错误类型整理为专项 Bad Case 包，推动在切题前增加方向与角度检测，先转正再切题；同时保留原图兜底，避免旋转服务异常导致整卷流程中断。

展开查看方案分工与三层复测

方案分工：算法侧负责旋转检测与切题模型优化；后端调整处理顺序，并保存旋转角度与坐标映射，确保批改痕迹能够还原至原始试卷；旋转服务异常时回退原图处理，避免整卷链路中断。

  • 第一层｜单节点验证：在切题节点评测集上验证节点指标不回退。
  • 第二层｜专项复测：重跑本轮倾斜 Bad Case，验证具体问题修复率。
  • 第三层｜端到端回归：在固定试卷集上重新运行全链路，确认 OCR、参考题匹配及最终判题没有回退。

三层验证通过后再进入灰度上线与线上监控，并将典型样本持续回流评测集。

05｜我的角色与方法沉淀

策略设计

推动知识点 RAG 接入讲题链路，设计知识点分层使用与降级机制；独立设计“最低相关性阈值 + Top1/Top2 分差”匹配策略，并通过历史错配 Bad Case 专项回归验证改善效果。

生产选型

围绕固定扩容与外部 API 按量兜底进行成本权衡，基于200条真实溢出请求完成5个候选模型及 Prompt 组合评测，综合识别效果、错误风险与成本推动确定 OCR 峰值兜底模型。

质量闭环

建立真实试卷分层抽样、端到端回放与首错归因机制，推动问题进入“定位—提单—优化—分层复测—Bad Case 回流”的持续迭代闭环。

方法沉淀：AI 产品质量不只取决于单点模型能力，还取决于上游错误传播、异常兜底与持续评测机制。策略设计和模型选型需要同时考虑效果、错误风险、稳定性与成本，并通过可回归、可验证的质量闭环持续迭代。
